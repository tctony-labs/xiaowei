## 容器内管理命令约定（待实施）

部署镜像包含 `xiaowei-server` 二进制。邀请签发由该二进制的 `invite` 命令完成，不提供 HTTP 签发接口。通过 `docker compose exec` 在现有服务容器内启动独立进程，使用容器网络、环境变量和挂载配置连接 PostgreSQL，完成后退出；HTTP 服务继续运行。

`exec` 的目标是 Compose 服务名，例如当前部署草稿的 `server`，不是镜像名或容器名。执行时必须定位到启动服务时的同一个 Compose 项目：

- 使用启动时的 Compose 文件组合及顺序，通过 `-f` 明确指定；当前草稿由依赖清单和服务端补充清单组合。
- 只有可发现默认命名的 Compose 文件，或已设置正确的 `COMPOSE_FILE` 时，才可省略 `-f`。
- 保持启动时的项目名；若启动时指定了 `-p`，执行管理命令时也使用该项目名。
- 保持所需的 `--env-file` 和配置解析上下文，使 Compose 能正确解析文件及变量。

Compose 的 `--env-file` 用于 Compose 配置解析，不等同于二进制的 `--config`。`exec` 启动的进程不会自动继承服务启动命令的参数；邀请命令需要显式指定容器内的 YAML 配置路径，或使用后续确定的统一默认路径。它通过容器网络中的数据库服务名连接 PostgreSQL，无需经过宿主机映射端口。

这些是后续部署命令必须满足的约束，不依赖当前仓库目录结构；具体文件放置、二进制路径与可直接执行的命令在部署切片中确定。
