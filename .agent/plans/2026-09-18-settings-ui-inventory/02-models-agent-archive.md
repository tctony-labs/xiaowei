# 第二部分：剩余模型与智能体设置

关联 [设置 record](../../records/active/2026-09-18-settings-ui-inventory.md)。远程模型配置及对话归档已由对应事项交付，本计划不重复实施：模型配置见[LLM provider](../../../docs/llm-provider.md#settings-模型配置与持久化)，归档／删除及自动策略见[Agent 运行与 UI](../../records/active/2026-09-28-agent-chat/runtime-ui.md#设置归档管理)。

## 剩余范围与前置

本地模型、图片生成配置和智能体设置仍未接产品。当前已有文本 Agent，但基础工具循环和搜索工具尚未实现；设置显示数值不等于执行能力生效。账号登录／云凭据、图片内容提取与自动更新仍暂缓。

远程模型采用独立 JSON／API Key 环境变量方案，Agent 会话目录由 xw-agent 自管；原本将这些数据放 Storage Settings／统一 credentials.ts 的草案不再作为实施依据。后续网络搜索源凭据需要在对应业务范围确认 owner 与保存边界后再落地，不据此改写现有模型配置。

## 实施顺序与文件

| 类型 | 文件／位置 | 剩余改动 |
| --- | --- | --- |
| 修改 | `desktop/src/renderer/src/components/settings/{SettingsPage,ModelSettingsPage,ModelSettings}.tsx`及测试 | 在真实本地模型／图片生成能力确定后接对应入口，沿用现有模型字段与预览，不模拟下载进度或仅凭目录推断生成能力 |
| 修改 | `desktop/src/renderer/src/components/settings/AgentSettings.tsx`及对应容器／测试 | 接工具上限和网络搜索源的实际配置与消费，覆盖 Key 测试、删除／回退和保存失败；产品容器位置实施前复核 |
| 待业务边界确定后列出 | 本地模型管理、图片生成、搜索源的 service／proto／handler | 先核对旧版业务、存储、文件生命周期及恢复，再确定契约和实际模块；不预建无消费者接口，不默认将业务移到 main |
| 修改 | 本事项 record | 回填实际 UI、偏差与验证，删除已完成计划 |

1. 本地模型先核对下载、校验、解压、重试、目录打开和切换的服务边界；验证磁盘／内存、资源文件及失败恢复，再接真实 UI。
2. 图片生成配置只在有真实可用的生成能力后接入；第三方调用由用户主动操作，不用请求模型目录代替生成验证。
3. 智能体配置必须由 Agent 执行循环消费工具上限；搜索源参考旧 Bing／Tavily／Brave／Serper 行为，Key 删除回退、鉴权／限流错误分别验证。与 Agent 工具计划协调，不另建第二套运行时。
4. 各能力就绪后更新 SettingsPage 的产品范围和跨窗口／重启测试；其余预览入口保持未接入，不把整个第二部分标为完成。

## 验证

自动测试使用临时文件／本地服务，覆盖配置与模型引用有效性、下载生命周期、失败／取消、真实执行限额与搜索错误。运行受影响的契约、Rust／napi、desktop check／test及预览检查；实际网络、下载和原生窗口由用户启动当前工作区后验收。

本计划只保留未交付范围，不继续拆分；实施前补齐对应业务的具体文件／接口并按仓库要求取得新增模块授权。完成后回填 record 并删除。
