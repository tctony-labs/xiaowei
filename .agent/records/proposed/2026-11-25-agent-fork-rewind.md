# Agent 会话 Fork 与 Rewind

## Why

用户需要从已有对话的某个位置尝试不同方向。该能力从 [Agent Chat](../archived/2026-09-28-agent-chat.md#后续提案) 的历史与运行控制扩展中拆出。

## What

- **Rewind** 更新原会话的有效上下文，从指定历史边界继续。
- **Fork** 从指定历史边界创建可独立继续的会话，保留来源会话及分叉位置。

## How

沿用现有 Session、Run、Item 的身份和历史顺序。优先考虑已完成的用户轮次作为入口，更细粒度的边界须能重建有效上下文，并保持工具调用和结果配对完整。选择边界时需考虑压缩检查点覆盖的范围。

Rewind 前停止并结算当前运行，保留已提交记录及外部副作用。Fork 从已提交历史开始，历史工具结果可用于上下文，在途任务、待处理输入和一次性授权属于原会话。旧事件仍归属原运行。两种操作都沿用已提交的工具结果。

## Current work

首次支持的历史边界、操作入口、并发校验和历史存储方式待设计。Fork 的历史存储可评估复制或共享不可变前缀。
