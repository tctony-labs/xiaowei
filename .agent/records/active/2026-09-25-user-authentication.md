# 用户、注册与登录方案

## Why

用户于 2026-09-25 要求开始讨论并记录用户与登录实现方案。登录后的业务通信使用 WebSocket；需要考虑邮箱注册／登录、中国用户使用微信登录的便利性，以及第三方自行部署服务器、客户端配置服务器地址的完整流程。

此前[设置窗口事项](2026-09-18-settings-ui-inventory.md)暂缓账号与云连接，仅保留模拟 UI；[Gateway 事项](2026-09-18-implement-gateway.md)记录了远端双向 WebSocket、连接认证与会话授权边界。本事项从服务端存储基础开始推进，桌面账号 UI 与远端通信仍按各自后续切片实施。

## What

已明确的需求：

- 登录后通过 WebSocket 与服务器通信。
- 先做邮箱注册与登录；微信作为第三方登录身份绑定到已有账号。本轮只考虑邮箱与微信，不设计 Facebook、WhatsApp 等其他接入。
- 用户明确要求设置密码，日常使用邮箱加密码登录，不采用每次通过邮箱验证码登录的方案。
- 用户表使用内部自增主键 `id`，对外使用独立生成的随机 `user_id`，两者保存在同一条用户记录中。
- 服务端默认 HTTP 端口为 `10001`；本地监听 `127.0.0.1:10001`，容器监听 `0.0.0.0:10001`，Compose 对宿主机映射 `127.0.0.1:10001`。PostgreSQL 端口仍为 5432。
- 服务端以 YAML 文件为主配置，部分字段支持明确的环境变量覆盖，方便测试与临时调整；不自动让所有字段可覆盖。
- 第一版统一使用标准 SMTP 发信，不接服务商专用 HTTP 发信 API。SMTP 凭据由测试或服务器部署环境提供，不进入客户端或版本库。
- 支持他人自行部署服务器，客户端可配置服务器地址。
- 服务端最终以 Docker 镜像形式交付部署，数据库采用 PostgreSQL；应用与数据库在同一主机分容器运行。
- 不使用 SQLite，第一版仅考虑单机部署，不设计多机部署能力。
- 各服务器账号独立；注册支持开放、邀请和关闭三种策略，自部署默认邀请注册。
- 客户端默认官方服务器地址，允许修改，第一版同时只连接一个服务器。
- 自动保持登录，支持多设备；退出撤销当前会话，重置密码撤销全部会话。
- 实施顺序为先完成邮箱注册、密码登录与找回密码，再接入微信绑定和登录。
- 提前考虑身份归属、部署依赖、服务器切换与会话隔离。

用户已要求开始第一个切片，并于 2026-09-26 确认 PostgreSQL；先通过 plan-align 对齐后，已于 2026-10-03 开始切片 01 实现与验收，其余切片仍未开始。方案收敛应覆盖：新用户如何加入、已有用户如何登录和恢复访问、部署者如何开放或限制注册、客户端如何选择服务器，以及登录会话如何用于 WebSocket。

用户明确收藏问题先不考虑；收藏上传、同步与迁移不在本轮讨论或实施范围内，不在此预先决定切换账号后的收藏处理行为。

## How

用户已确认 What 中的产品方向与边界；下文标为建议或候选的技术细节仍待实施设计，所有认证能力尚未实现。

### 当前实现依据

实施前 Go 服务端仅有健康检查与 HTTP 生命周期。切片 01 已新增 YAML 配置、PostgreSQL 用户存储、启动迁移与 `/readyz`；尚无认证接口或 WebSocket 接入。设置中的微信登录、UIN 和账号状态是旧版参考与预览，不是新版已实现的账号协议。

### 账号归属与数据模型

已确认每个服务器部署独立管理用户，不要求自部署用户先注册官方账号。客户端以“服务器身份／地址 + user_id”区分账号；相同邮箱或微信身份在不同服务器上不自动代表同一个业务账号，不自动合并账号。

已确认用户表同时保存内部自增整数主键 `id` 和稳定的随机公开标识 `user_id`。创建用户时，数据库生成 `id`，后端使用密码学安全随机源生成 128 位随机值，以无填充 Base64URL 编码为 22 位字符串并加 `u_` 前缀作为 `user_id`。公开标识设置唯一约束，随机碰撞时重新生成；它不是自增数字的编码、哈希或可逆转换，不采用 UUID 文本格式。

例如，同一行用户记录可以保存 `id = 12345` 和 `user_id = u_7mK2qR9xW4nT8bYpC6dHfA`。通过公开标识的唯一索引查询这条记录即可取得内部主键，不需要解码。内部业务表以自增主键关联用户，对外 API、客户端与 WebSocket 中的用户标识使用公开 `user_id`，不返回内部主键。随机标识降低枚举风险，但不替代认证和数据归属校验；当前用户必须由服务端验证的会话确定。

用户资料、登录身份与设备会话分开：一个用户可绑定邮箱及微信身份，一个用户可有多个可撤销的设备会话。内部主键和公开标识均独立于登录方式；邮箱和微信 OpenID 不作为业务表的用户主键。

绑定另一种登录方式时，必须验证当前账号与待绑定身份；不因昵称相同、客户端声明或未经验证的邮箱相同而自动合并账号。微信身份需包含应用范围；OpenID 不能直接跨应用复用，UnionID 是否可得与其关联条件需要在选定微信产品后核验。

### 邮箱注册与登录

已确认使用邮箱加密码作为基础登录入口，用户认为每次收取邮箱验证码过于麻烦。建议注册时验证邮箱归属并设置密码；日常登录只验证邮箱与密码；忘记密码时通过邮箱验证码验证后设置新密码，不提供验证码直接登录入口。

已确认注册策略由部署者配置为开放注册、邀请注册或关闭注册，自部署默认邀请注册。关闭注册不阻止已有用户登录；邀请需要校验有效期、使用次数及必要的邮箱约束。建议首个管理员通过部署端的一次性初始化流程建立，不能把公网第一个注册者自动设为管理员；邀请签发与管理员初始化的具体入口在实施设计中确定。

验证码需要有效期、单次消费、尝试次数限制和按邮箱／来源限流；发送响应避免泄露账号是否存在。SMTP 凭据只存在服务器端，发送能力与投递失败需有可诊断结果。邮件用于注册验证、密码重置等操作，日常密码登录不依赖邮件服务可用；邮件服务成本与中国常用邮箱投递情况需要验证。

密码仅保存带独立盐的密码哈希，建议采用 Argon2id，参数在实施时按服务端资源评估；不保存明文或可逆加密密码，不记录密码和验证码。密码登录需要限流，错误提示不区分邮箱不存在和密码错误。已确认密码重置完成后撤销该账号全部旧会话并关闭关联 WS，要求重新登录。首期邮件验证注册与自助找回密码依赖 SMTP；无 SMTP 的独立开户与恢复模式不纳入当前建议范围。

已确认第一版通过标准 SMTP 接入现成邮件服务，不自行部署收发邮件服务器，不接服务商专用 HTTP 发信 API。部署者配置 SMTP 主机、端口、TLS 模式、用户名、密码或授权凭据，以及发件地址和名称；凭据保存在部署者提供的后端 YAML 配置或通过允许的 env／部署 Secret 覆盖，不进入客户端或版本库。普通邮箱、企业邮箱与支持 SMTP 的事务邮件服务使用同一套配置结构，实际认证凭据由服务商决定，不统一称作邮箱授权码。个人小规模部署可使用允许 SMTP 发信的现成邮箱，公开服务可使用事务邮件服务及已验证的发信域名，按服务商要求配置 SPF／DKIM 等 DNS 记录。具体供应商尚未选定。

建议测试与生产使用独立凭据，仓库仅提供不含真实凭据的配置示例。当前已实现 YAML 主配置，加载同目录的可选 `.env`，外部进程 env 具有最高覆盖优先级。SMTP 字段将在切片 03 增加。

应用后端负责生成和校验验证码，邮件服务只负责投递。先验证测试邮件可达，再验证验证码过期、用途隔离、单次消费、密码登录限流、会话建立与重置密码后的会话撤销。普通客户端用户无需配置 SMTP；未配置发信服务的部署无法完成邮件验证注册与自助密码重置。

### 建议的首期用户流程

以下流程基于已确认的邮箱加密码登录方向，具体交互与恢复策略为建议：

1. 客户端选定服务器并读取公开登录能力，显示当前服务器地址。
2. 新用户选择注册，输入邮箱、验证码并设置密码；服务端再次检查注册策略，验证邮箱归属，在事务中消费验证码并创建包含密码哈希的唯一账号，随后建立会话。并发注册不能创建重复账号。
3. 已有用户选择登录，验证邮箱与密码后建立设备会话；不存在的账号不在登录流程中静默创建。
4. 客户端保存会话并连接 WSS；下次启动先尝试恢复会话，失效后才要求重新登录，临时断网不等同于退出登录。客户端保存会话凭据，不保存登录密码。
5. 微信入口实施后，已登录用户在账号设置完成微信授权并绑定；已经绑定其他账号的微信身份拒绝再次绑定。以后微信登录进入同一 user_id，未绑定身份引导先通过邮箱登录。
6. 忘记密码时，用户通过邮箱验证码验证后设置新密码；消费验证码、更新密码哈希和撤销旧会话应保持一致，再返回密码登录入口。验证码绑定邮箱与操作用途，注册、重置密码和邮箱绑定／更换不能互用。

邮箱更换与微信解绑属于敏感账号操作，应要求近期身份验证；更换邮箱还需验证新邮箱归属，并保证唯一绑定。不得解绑最后一种可用登录方式。丢失邮箱且无可用绑定身份时不自动恢复或合并账号，具体恢复政策待定。

### 微信绑定与登录

用户已确认先完成邮箱注册、密码登录与找回密码，再接入微信绑定与登录。微信作为第三方身份绑定到已有账号上：用户先完成邮箱注册／登录，再在账号设置中绑定微信；之后可通过微信登录同一账号。未绑定的微信身份不直接创建独立账号，提示先通过邮箱登录并绑定。服务器公布微信是否启用。

桌面端可评估系统浏览器中的微信扫码授权：服务器创建短期登录事务，浏览器完成微信授权，服务器校验回调并换取身份，原客户端凭一次性事务凭据获取本应用会话。回调校验 state，登录事务绑定发起客户端，客户端凭据与浏览器公开参数分开，禁止其他客户端领取结果；短期结果只消费一次。微信 secret 与授权码交换在服务器完成，长期会话令牌不放在回调 URL 中。

具体采用微信网站应用扫码、移动应用登录或其他微信产品，须按目标平台核验当前开放平台资质、审核、回调域名与应用关联要求；本记录未完成这部分外部核验，不保证任意个人部署者均可开通。移动端也不能直接假设复用桌面扫码流程。

第三方部署者默认配置自己的微信应用凭据与回调域名；未配置时客户端隐藏微信入口，邮箱等基础入口仍可用。不向部署者分发官方微信 secret。若未来希望自部署统一使用官方微信登录，需要另行设计官方身份中介及对各服务器的信任、授权和身份映射；该方案带来官方在线依赖，不纳入初期建议。

### 客户端服务器设置

已确认客户端默认使用官方服务器地址，允许修改，第一版同时只连接一个服务器；官方实际地址在发布配置时确定。建议以一个基础 HTTPS 地址发现服务名称、协议兼容版本、可用登录方式与注册策略，再展示登录 UI。发现响应只能提供公开能力，不暴露任何服务端凭据。HTTP API 与 WSS 路径从同一基础地址按约定派生，考虑反向代理子路径，不要求用户分别填写 HTTP 和 WS 地址。

公网使用 HTTPS／WSS；本地开发例外另行界定，不默认跳过证书验证。部署配置应明确外部访问地址、TLS／反向代理、邮件服务、注册策略及可选微信回调设置；内部监听地址不能直接当作对外回调地址。

切换服务器时终止旧连接并取消在途登录事务，新请求使用新服务器的独立会话；不得把旧服务器的 token、验证码或微信授权结果发送给新服务器，跨域重定向也不能转发凭据。客户端清楚显示当前连接的服务器，服务器名称只是展示信息，不能代替实际地址与 TLS 校验。

本地普通剪贴板等离线功能继续可用。账号与连接状态按服务器隔离，修改服务器地址不自动合并账号。收藏上传、同步与迁移按用户要求暂不讨论，后续在对应事项中决定。

### 会话与 WebSocket

已确认自动保持登录并支持多设备会话，退出登录撤销当前会话，重置密码撤销该账号全部会话。具体过期时长与刷新参数在实施设计中确定，自动保持登录不表示会话永不过期。

建议通过 HTTPS 完成能力发现、注册验证、邮箱密码／微信登录、密码重置、会话刷新与退出，再使用应用自身的会话认证建立 WSS 业务连接。登录成功前没有认证后的 WS 是正常状态，不要求先建立业务 WS 才能登录。

候选方案为短期 access token 加可轮换、可撤销的 refresh token，具体 token 格式待定。服务端保留设备会话与撤销状态，refresh token 不明文存储；客户端长期凭据通过操作系统安全存储保存，不放入普通 renderer localStorage 或日志。

原生连接端可在握手时携带认证信息；若所选 WebSocket API 不支持认证请求头，可通过 HTTPS 换取短期一次性连接票据。避免将长期 token 放入 WS URL。连接成功后绑定服务端验证得到的 user_id 与 session_id，不信任业务消息自报的用户身份。

退出、撤销设备或禁用用户应使相关 WS 失效；access token 到期后，连接需有明确的重新认证或重连策略，不能只在初次握手校验而永久有效。业务请求仍需校验数据归属和权限。网络离线与登录失效分别展示，临时断网不删除长期会话。

远端服务导出、断线清理与不自动重放写操作继续遵循 Gateway record；会话令牌方案不改变这些约束。

### 运行配置与本地开发

日常使用 Docker 管理 PostgreSQL，Go 在本机运行和调试。开发依赖清单只定义数据库等依赖，不包含小微 server；`just prepare-server` 只检查本地配置文件是否存在并启动清单内全部服务；配置缺失时只输出复制命令与重新运行提示，不自动生成文件，不预检查 .env 内容，配置正确性由 Docker Compose 与 Go server 启动时保障。`just server` 先执行准备，再通过 `scripts/dev/server.mjs` 启动本机 Go，终端按 `r` 只重新编译并重启 Go，按 `R` 停止 Go、重建依赖容器并等待就绪，再启动 Go。重建保留数据库数据卷；退出先清理 Go 进程组，再对同一 Compose 项目执行 stop，保留容器与数据卷，下次准备时通过 up 重新启动。当前固定使用 xiaowei-dev 项目，多工作区共享这组依赖时也会一起停止。重启操作串行，退出会取消在途依赖准备并跳过后续启动。

当前开发配置集中在 `server/config/`。主配置使用 YAML，指定字段允许覆盖，优先级为默认值 < YAML < YAML 同目录的可选 .env < 外部进程 env。Go 与 Compose 共用同一 .env，数据库密码只填写一次。两份配置模板均使用用户指定的本地开发密码 `password`，复制后无需另行填写密码；程序仍要求密码非空。具体运行入口见 [服务端 README](../../../server/README.md#本地开发)，字段映射与校验见下文“配置与存储”。

用户已确认启动时自动执行数据库迁移，完成后才开放 HTTP；失败回滚并退出，不自动清库或降级。当前已实现，验收结果见 Outcome。

#### 配置与存储

程序默认读取当前工作目录下的 `config/server.yaml`；`just server` 在 `server/` 中运行。可以在 `server/` 中直接指定其他路径：

```sh
go run ./cmd/xiaowei-server --config /path/to/server.yaml
```

优先级为 **内置默认值 < YAML < YAML 同目录的可选 .env < 外部进程 env**。主文件必须存在，未知字段、重复键、错误类型及多份 YAML document 会使启动失败。配置仅启动时读取，修改后需重启；YAML 不提供变量插值，配置不热更新。

| YAML 字段 | env 覆盖 | 默认值／要求 |

显式设置的空 env 也会覆盖 YAML，并按字段规则校验，不会回退。程序使用 godotenv 读取 YAML 同目录的可选 `.env`，只应用明确列出的键，不修改进程环境；缺失文件允许继续，不可读或解析错误则安全报错，不回显内容。修改 `--config` 后 `.env` 跟随 YAML 目录，不从 cwd 另找文件；也不接受 libpq 的 `PG*` 环境变量作为额外配置来源。共享密码包含 `$` 或 `#` 时应使用单引号保证 Go 与 Compose 按字面量读取。

#### 启动、迁移与健康检查

启动顺序为读取配置 → 连接 PostgreSQL → 执行迁移 → 监听 HTTP。任一步失败则退出，不提前开放 HTTP。连接建立超时 5 秒，连接与迁移总超时 30 秒，连接池最多 10 个连接。

迁移 SQL 通过 `go:embed` 打包，使用 UTC `YYYYMMDDHHMMSS` 时间戳版本；Go 使用 int64，`schema_migrations.version` 使用 bigint，另保存 SHA-256 与应用时间。启动事务获取 advisory lock，按版本核对当前代码已知迁移的校验和，再将当前代码中尚未执行的迁移按时间戳排序执行并登记，整体提交。登记列表中的重复时间戳或无效日期会拒绝执行；失败回滚本次迁移，不清库、不自动降级。

切换或回退分支时，数据库中存在当前代码不认识的迁移只输出日志提示，保留其表结构与历史，不阻止启动。已执行的较晚迁移不阻挡合并后较早但尚未执行的迁移；这些补执行 SQL 仍须兼容数据库当前结构。已知迁移的 SQL 校验和变化仍会拒绝启动。兼容规则要求分支包含本次迁移器更新，更早的严格实现不会自动改变。

`001_users.sql` 已改名为 `20260925000000_users.sql`，SQL 内容未变。开发期本地数据库已通过一次性 SQL 将历史字段改为 bigint、版本 1 改为 20260925000000，保留校验和、原执行时间与用户数据。运行代码不保留旧序号或 integer 历史字段的特殊兼容逻辑。

新增迁移时使用 UTC 时间戳文件名，例如 `20261003143000_add_email.sql`，并在 `internal/db/migrate.go` 中嵌入、登记同一版本；不要修改已应用的迁移。为兼容旧分支，新增字段应允许为空或提供合适默认值，查询显式列出所需字段。未知迁移造成的实际结构不兼容由业务 SQL 调用报错，而不是仅凭迁移版本阻止服务运行。

| 接口 | 含义 | 响应 |
| --- | --- | --- |
| `GET /healthz` | 进程可响应 | 200，`{"status":"ok"}` |
| `GET /readyz` | 数据库当前可用；探测超时 2 秒 | 200，`{"status":"ok"}`；失败返回 503，`{"status":"unavailable"}` |

可从宿主机检查：

```sh
curl -f http://127.0.0.1:10001/healthz
curl -f http://127.0.0.1:10001/readyz
```

数据库中断时进程继续运行，readiness 返回 503；连接恢复后 readiness 可恢复。SIGINT／SIGTERM 先停止 HTTP，最多等待 5 秒，再关闭数据库池。日志输出到进程标准错误，记录配置读取、迁移结果和服务生命周期；不输出密码、完整 DSN 或原始 YAML 值。

用户表当前仅包含内部 bigint identity 主键 `id`、公开 `user_id` 和创建时间。公开 ID 使用 128 位安全随机数，编码为 `u_` 加 22 位无填充 Base64URL；数据库精确区分大小写并保证唯一。内部 ID 不参与 JSON 序列化。创建用户存储记录不代表完成注册，本阶段没有对外开户接口。

## Alternatives considered

- 官方统一账号覆盖所有自部署服务器：跨服务器体验可能更一致，但增加中心依赖、第三方服务器信任与账号授权问题，已确认使用独立账号体系。
