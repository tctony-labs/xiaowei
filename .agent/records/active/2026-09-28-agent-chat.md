# Agent Chat：Agent Core 与聊天 UI

## Why

事项开始时 Quick Chat 已具备 Launcher 入口、键盘与窗口交互、模型配置引导，以及真实模型的多轮文本／思考流式回复。模型层已经 ready：现有 LLM worker 和 Gateway 契约支持完整消息、工具声明与工具结果、流式内容块、用量、取消和 Rust typed caller，无需另起一套模型接入。

缺口在模型调用之上的 Agent Core 和对应 Chat UI。事项开始时 `useQuickChat` 在 renderer 内存中保存消息并直接调用 `Llm.Generate`，每次发送只进行一次模型生成；不执行工具，收到工具调用即报错，也没有持久会话、运行恢复或真实会话管理。仅把工具输出展示到现有文本面板，不能形成完整的 agent 对话闭环。

本事项承接 [Quick Chat 入口与内存对话](2026-09-24-quick-chat-ui-interaction.md) 和 [LLM provider](2026-09-24-llm-provider.md)，将 Quick Chat 升级为真实 Agent Chat 的产品入口。现有事项仍承载已经生效的行为，本事项按职责更新它们的当前说明。

## What

### 目标与范围

这里的“完整”指用户可持续使用的 agent 对话闭环：发送消息 → 模型生成 → 必要的工具执行／授权 → 工具结果回传 → 后续生成 → 明确终态，并能保存、重新打开和继续会话。首期范围已于 2026-09-29 确定，按下述范围分片实施。

- **Agent Core**：以旧版 Rust 实现为迁移基础，在 renderer 之外持有会话与运行状态，负责系统指令、上下文组装、模型调用、工具循环、取消、失败及运行限制。沿用现有 Rust agent → Gateway → TS LLM worker 的架构方向，参考 Codex 源码完善设计。
- **工具执行**：定义工具注册、参数校验、调用与结果关联、错误返回及取消边界；交付实际可用的首批工具，不能仅用 mock 工具作为产品完成依据。需要授权的工具包含请求、允许、拒绝与失效处理。
- **持久会话**：保存会话元信息、有序消息、工具执行记录、运行终态与必要回放元数据；支持新建、列表、切换、重命名、归档、删除和重新打开后继续对话。自动标题／更新标题与现有预览操作一起接入。
- **Chat UI**：展示 Markdown／代码、思考内容、工具调用及结果、等待授权、生成中、停止、失败和中断状态；具备输入、发送、停止、消息复制和明确的失败重试入口。会话模型／思考强度选择对接现有设置与模型能力。
- **Quick Chat 接入**：保留已确认的 Launcher 展开／收起、快捷键、焦点、输入法、滚动及模型空态行为，以 Agent 会话替换 renderer 内存会话；复用已存在的完整标题栏和会话菜单，不重做入口。

### 非目标与范围边界

不重写 Pi provider、模型设置或 Gateway，不恢复已明确移除的“在外部对话窗口打开”按钮。本事项不默认扩展为独立聊天窗口、Studio、多人／多 agent 协作、云同步或任意插件平台。

2026-09-29 用户确认首期保留旧版自动压缩、自动／手动标题生成，输入沿用现有 textarea，展示 Markdown／代码和工具卡片。附件／图片输入、富文本编辑器、Skills／命令资源加载、旧会话数据导入及完整旧版工具集留到后续；不以“完整”宣称已全面对齐旧版。工具返回的数据仍须保留现有 LLM 契约支持的内容，不能因首期不提供图片输入 UI 而丢失回放元数据。

2026-09-29 规划时已确认首期采用基础工具闭环：文件读写／搜索、Bash、网页读取、用户询问与权限申请；依赖搜索服务配置的 WebSearch、应用专属工具和插件留到后续。具体工具接入、后台进程和交互请求的生命周期在实施计划中对齐旧版。

follow-up、steering、preempt、rewind、fork 本期要求在设计上留好扩展空间，不默认要求交付相应功能或 UI。旧版已经具备的相关机制先核对再复用，不一概当成缺失能力，也不为预留能力提前引入通用调度框架或完整分支系统。

### 完成标准

1. 从产品 Quick Chat 发送消息，实际经过 Agent Core 和既有 LLM worker；纯文本多轮、思考回复与至少一个真实工具的“调用 → 结果 → 继续生成”均可完成。
2. 同一次用户发送可以包含多次模型调用与多个工具结果；UI 顺序、工具关联和最终状态与 core 一致，不把一次 `TOOL_USE` 当成整轮完成。
3. 停止覆盖等待模型、生成、工具执行与等待授权；无法撤销的工具副作用明确呈现。停止后不会再启动下一次生成，迟到事件不会污染其他运行或会话。
4. 会话切换、Launcher 隐藏／重新显示、renderer 重载和应用重启后，历史、状态与下一轮上下文符合约定；不会重复发送消息或自动重放有副作用的工具。
5. 新建、切换、重命名、归档与删除操作接真实数据；持久化失败可见，删除后不会被迟到写入复活。失败重试不重复已完成的工具副作用。
6. 工具非法参数、未知工具、拒绝授权、模型失败、无终态断流、上下文超限及存储失败都有可验证的终态或恢复路径；不能永久停留在“生成中”。
7. 本轮用户明确跳过 Storybook，直接实现 composer／hint 并经产品验证；通过相关 core、Gateway、存储及 renderer 自动检查，并在 Electron 验证真实模型／工具链路、平台键盘与窗口行为。模拟流、构建通过不能代替产品验收。
8. 契约、运行循环与持久化设计经过扩展性检查：用户输入接纳与模型调用分离，历史条目有稳定身份，上下文构建不依赖“整个会话数组就是唯一历史”。说明上述后续能力的接入点及迁移路径，不以未实现的空接口或按钮作为验收证据。

## How

采用旧版 Rust Agent 迁移路线，复用现有 LLM worker 与 Gateway。当前已交付持久文本聊天里程碑：Quick Chat 通过 Agent 控制 API 调用 xiaowei-agent／xw-agent；xw-agent 是 App Server，持有权威会话、运行与投影，直接管理 SQLite 会话目录；JSONL 保存模型配置与执行历史。宿主通过统一 AgentHost 提供模型能力，核心不依赖外部业务 service。

## Alternatives considered

- **继续扩展 renderer hook**：可快速加入一次工具调用，但会话寿命仍受窗口与 React 生命周期影响，持久化、恢复和工具授权难以形成单一权威状态，不作为完整 Agent Core 的方向。
- **在 LLM worker 内加入 agent 循环**：会将模型适配与会话／工具业务混合，偏离现有 Rust 调用边界，不采用。
- **基于 TS Pi Agent Core**：讨论过直接复用上游循环与 harness 的方向，用户最终选择旧版 Rust 迁移。此决定不表示 Pi 缺乏工具、队列或持久化能力；本事项不再以替换为 Pi Agent 为前提推进。
- **直接整体搬入旧 agent 与 UI**：旧版模型协议、宿主和存储边界不同，不能原样接入；先核对业务、恢复和文件生命周期，复用有效语义并显式记录适配差异。

## Outcome

截至 2026-10-07，已交付可跨重启使用的文本 Agent Chat：多轮文本／思考、停止／错误、模型与思考切换、自动／主动生成及手动设置标题、会话列表／切换／归档／恢复／删除和自动维护。Quick Chat 不再直接调用 Llm.Generate，新建保留旧会话，启动恢复最后更新的未归档会话。composer 外部右上方 chip 样式已由用户确认。

正式 Rust core、Gateway／napi、main 生命周期及 renderer 已接通；JSONL 当前为 Header／Meta 分离的精简 v2，SQLite 管理标题及会话状态。开发数据按授权清理和离线调整，代码只保留当前格式，不交付旧数据导入或运行时迁移。

最新 Rust 122 项、严格 no-deps Clippy、正式 Agent addon 重建与 5 项 Gateway／真实 worker 测试、just check 通过；此前完整 desktop 回归的 renderer 20 文件／139 项通过。真实两轮对话及标题日志、正式入口的数据副本连续重开、当前实例加载与最近会话恢复均已验证。详细证据与人工验收限制见[交付证据](2026-09-28-agent-chat/implementation-results.md)。本次整理仅修改文档，未重跑业务测试。
