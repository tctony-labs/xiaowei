### SMTP、邀请与邮箱注册（03，尚未实现）

已确认使用邮箱加密码作为基础登录入口，用户认为每次收取邮箱验证码过于麻烦。建议注册时验证邮箱归属并设置密码；日常登录只验证邮箱与密码；忘记密码时通过邮箱验证码验证后设置新密码，不提供验证码直接登录入口。

已确认注册密码为 6–32 个字符，仅允许可打印 ASCII 字符（英文、数字、符号和空格），不支持中文，不强制大小写、数字或符号组合。不去除首尾空白、不改变大小写，按原始密码计算 Argon2id 哈希；不保存明文。此规则约束新密码设置，登录继续按原值校验已有密码。

已确认注册策略由部署者配置为开放注册、邀请注册或关闭注册，自部署默认邀请注册。关闭注册不阻止已有用户登录；邀请需要校验有效期、使用次数及必要的邮箱约束。首个管理员通过已确认的服务端环境变量初始化建立，不能把公网第一个注册者自动设为管理员；邀请签发使用下述服务端命令，仍待实施。

已确认邀请签发只通过服务器端 `xiaowei-server invite` 命令执行，不提供公开 HTTP 签发接口，不增加 `create` 子命令。提供 `--email` 时绑定该邮箱且固定使用一次；未提供邮箱时必须通过 `--uses` 指定正整数使用次数，可以大于一次。邀请码只有在注册事务成功时才扣减额度，并发注册不得超额使用。命令读取服务端配置，直接连接数据库签发邀请；指定邮箱时自动通过 SMTP 向该邮箱发送注册链接，未指定邮箱时输出邀请码供分发，完成后退出；执行权限由服务器系统账号及数据库访问权限控制。有效期参数拟用 `--expires-in`，默认值尚待确定。

已确认邀请注册区分两条流程：

- 邮件链接注册：命令向绑定邮箱自动发送注册链接，链接携带邮箱及服务端签发的验证凭据。打开链接时校验邮箱与凭据的绑定关系、有效期和邀请状态，通过后进入注册页面；邮箱与邀请码由已验证的邀请确定，不允许用户修改，用户只需设置密码即可注册。有效链接凭据已完成邮箱归属验证，不再额外发送或要求输入邮箱验证码；验证依据是有效凭据，不依赖浏览器来源或“从邮件点击”的声明。注册提交时服务端再次检查凭据和邀请状态，不能只信任页面首次校验结果。打开链接不消费邀请或注册凭据，注册事务成功才一次性消费。
- 手动注册：用户自行填写邮箱并先收取邮箱验证码，同时在注册页面手动填写邀请码。提交注册时才校验邀请码的有效期和剩余额度，并校验该邮箱的 verification_id 与验证码；不以邀请码校验通过作为发送邮箱验证码的前提。只有注册事务成功才消费验证码和邀请额度，失败不消耗；错误验证码仍按已确认规则累计失败次数。开放注册模式不要求邀请码。

注册页面的承载位置，以及网页注册完成后的会话衔接仍待对齐。

部署时二进制包含在服务端镜像中，可在运行容器内启动独立邀请签发进程；同一 Compose 项目、文件组合、环境配置及容器内配置路径的定位约束见 [部署交付](../../../server/docs/deployment.md#容器内管理命令约定待实施)。邀请命令尚未实现，后续复用已有部署流程。

验证码需要有效期、单次消费、尝试次数限制和按邮箱／来源限流；发送响应避免泄露账号是否存在。SMTP 凭据只存在服务器端，发送能力与投递失败需有可诊断结果。邮件用于注册验证、密码重置等操作，日常密码登录不依赖邮件服务可用；邮件服务成本与中国常用邮箱投递情况需要验证。

已确认使用邮箱验证码的流程中，每次验证使用独立的随机 verification_id。发送接口返回该 ID 和到期时间，验证码仅通过邮件投递；服务端记录邮箱、用途、验证码哈希、失败次数、到期时间及消费状态。注册提交 verification_id 和验证码，服务端核对邮箱与用途后校验，并原子累计该记录的失败次数；第 5 次错误后记录失效。重新发送生成新的 ID 和验证码，新码发送成功后旧记录失效，客户端更新 ID，旧 ID 不能绕过尝试次数限制。注册成功时与账号及会话创建一起消费验证记录，事务失败不消费。验证码格式、有效期及发送限额的具体配置仍待收敛。

新流程复用已有 Argon2id 密码哈希及密码登录限流，不保存明文或可逆加密密码，不记录密码和验证码。现有参数和错误语义见 [认证文档](../../../server/docs/authentication.md)。已确认密码重置完成后撤销该账号全部旧会话并关闭关联 WS，要求重新登录。首期邮件验证注册与自助找回密码依赖 SMTP；无 SMTP 的独立开户与恢复模式不纳入当前建议范围。

已确认第一版通过标准 SMTP 接入现成邮件服务，不自行部署收发邮件服务器，不接服务商专用 HTTP 发信 API。部署者配置 SMTP 主机、端口、TLS 模式、用户名、密码或授权凭据，以及发件地址和名称；凭据保存在部署者提供的后端 YAML 配置或通过允许的 env／部署 Secret 覆盖，不进入客户端或版本库。普通邮箱、企业邮箱与支持 SMTP 的事务邮件服务使用同一套配置结构，实际认证凭据由服务商决定，不统一称作邮箱授权码。个人小规模部署可使用允许 SMTP 发信的现成邮箱，公开服务可使用事务邮件服务及已验证的发信域名，按服务商要求配置 SPF／DKIM 等 DNS 记录。具体供应商尚未选定。

建议测试与生产使用独立凭据，仓库仅提供不含真实凭据的配置示例。当前已实现 YAML 主配置，加载同目录的可选 `.env`，外部进程 env 具有最高覆盖优先级。SMTP 字段将在切片 03 增加。

应用后端负责生成和校验验证码，邮件服务只负责投递。先验证测试邮件可达，再验证验证码过期、用途隔离、单次消费、密码登录限流、会话建立与重置密码后的会话撤销。普通客户端用户无需配置 SMTP；未配置发信服务的部署无法完成邮件验证注册与自助密码重置。


### 注册、找回密码与客户端衔接（04–05）

以下串联目标流程中的注册、找回密码和第三方衔接仍未实现；已有密码登录与恢复复用当前桌面账号模块，新增交互仍需实施前对齐：

1. 客户端选定服务器并读取公开登录能力，显示当前服务器地址。
2. 新用户选择注册，输入邮箱、验证码并设置密码；服务端再次检查注册策略，验证邮箱归属，在事务中消费验证码并创建包含密码哈希的唯一账号，随后建立会话。并发注册不能创建重复账号。
3. 已有用户选择登录，验证邮箱与密码后建立设备会话；不存在的账号不在登录流程中静默创建。
4. 客户端保存会话并连接 WSS；下次启动先尝试恢复会话，失效后才要求重新登录，临时断网不等同于退出登录。客户端保存会话凭据，不保存登录密码。
5. 微信入口实施后，已登录用户在账号设置完成微信授权并绑定；已经绑定其他账号的微信身份拒绝再次绑定。以后微信登录进入同一 user_id；未绑定身份返回 binding_required，用户选择邮箱注册或密码登录，并携带 thirdparty_bind_token 完成绑定。
6. 忘记密码时，用户通过邮箱验证码验证后设置新密码；消费验证码、更新密码哈希和撤销旧会话应保持一致，再返回密码登录入口。验证码绑定邮箱与操作用途，注册、重置密码和邮箱绑定／更换不能互用。

邮箱更换与微信解绑属于敏感账号操作，应要求近期身份验证；更换邮箱还需验证新邮箱归属，并保证唯一绑定。不得解绑最后一种可用登录方式。丢失邮箱且无可用绑定身份时不自动恢复或合并账号，具体恢复政策待定。


### 能力发现与网页承载（03、05）

已有客户端使用一个基础服务器地址，建议增加公开能力发现以返回服务名称、协议兼容版本、登录方式、注册策略和微信是否启用；不能返回任何服务端凭据。HTTP 与 WSS 路径从同一基础地址派生并兼容反向代理子路径，不要求用户分别填写两套地址。

Vite／React 网页工程、注册页面承载和网页完成注册后的桌面会话衔接仍待对齐；Go 托管或 Nginx 静态托管的具体构建交付方式须结合实现确定，不提前新增 npm package。当前 Nginx 已将业务 API 与健康检查分流，其他路径为空页面占位，不能将此前讨论的 `/admin/` 路径视为已实现管理后台。

切服必须取消在途注册、验证码和授权操作，迟到结果不能覆盖新服务器状态；旧服务器 token、验证码和微信授权结果不得发送给新服务器。邮箱唯一约束和会话隔离继续由服务端保证，展示名称不能代替实际地址及 TLS 校验。

### 远端 Gateway 与 WebSocket（06，尚未实现）

建议通过 HTTPS 完成能力发现、注册、登录、密码重置、刷新和退出，登录成功后再建立认证 WSS。原生连接可在握手携带认证头；不支持该能力的 WebSocket API 可评估通过 HTTPS 换取短期一次性连接票据，避免长期 token 出现在 URL 中。连接绑定服务器验证得到的 user_id、device_id 和 session_id，不信任消息自报身份，设备 ID 不能单独授权推送。

业务推送可以寻址用户全部在线设备、指定设备或排除当前设备；具体协议与推送能力待设计。退出或撤销当前会话只使其连接失效；密码重置撤销账号全部旧会话并关闭关联连接，禁用用户同样应使连接失效。access 到期后必须有重新认证或重连策略，不能握手一次后永久有效。业务请求仍校验归属和权限，临时断网不清除仍有效的登录态。

双向调用、远端导出、连接实例隔离、断线清理以及不自动重放写操作的边界遵循 [Gateway 远端设计](../../../docs/gateway.md#远端服务与双向-websocket尚未实现)。业务方在 xwapi 中选择 HTTP／WebSocket 的方向已记录于 [传输选择](../../../docs/xwapi.md#后续-http-与-websocket-选择尚未实现)；统一连接管理，不由业务各自建连，免登录方法不能绕过 WebSocket 的连接认证。

06 分两步验收：先用测试服务验证 TS／Go Gateway 真实传输、路由与断线语义，再接真实设备会话及桌面状态。进入实现前明确事件、流取消、背压、心跳、重连、默认传输和未就绪行为；不能只完成 WS 握手就宣称远端 Gateway 完成，也不擅自跨传输重试结果不明的写请求。

### 微信绑定与登录（08，尚未实现）

用户已确认先完成邮箱注册、密码登录与找回密码，再接入微信绑定与登录。微信作为第三方身份关联小微账号。已登录用户从独立绑定入口发起授权，服务端将授权事务关联当前账号，验证回调后直接绑定，不先返回临时 token 再要求调用一次绑定。未登录用户发起微信登录时，已绑定身份直接登录；未绑定身份返回 binding_required，复用已验证身份完成邮箱注册或密码登录并绑定。服务器公布微信是否启用。

绑定必须同时验证当前账号与待绑定身份；不因昵称相同、客户端声明或未经验证的邮箱相同而自动合并账号。邮箱和微信 OpenID 不作为业务用户主键。微信身份需包含应用范围，OpenID 不能直接跨应用复用；UnionID 是否可得及其关联条件须在选定微信产品后核验。

桌面端可评估系统浏览器中的微信扫码授权：服务器创建短期登录事务，浏览器完成微信授权，服务器校验回调并换取身份，原客户端凭一次性事务凭据获取本应用会话。回调校验 state，登录事务绑定发起客户端，客户端凭据与浏览器公开参数分开，禁止其他客户端领取结果；短期结果只消费一次。微信 secret 与授权码交换在服务器完成，长期会话令牌不放在回调 URL 中。

具体采用微信网站应用扫码、移动应用登录或其他微信产品，须按目标平台核验当前开放平台资质、审核、回调域名与应用关联要求；本记录未完成这部分外部核验，不保证任意个人部署者均可开通。移动端也不能直接假设复用桌面扫码流程。

第三方部署者默认配置自己的微信应用凭据与回调域名；未配置时客户端隐藏微信入口，邮箱等基础入口仍可用。不向部署者分发官方微信 secret。若未来希望自部署统一使用官方微信登录，需要另行设计官方身份中介及对各服务器的信任、授权和身份映射；该方案带来官方在线依赖，不纳入初期建议。


### 第三方衔接事务（08，尚未实现）

登录和已登录用户的主动绑定采用独立入口，不通过公共 purpose 字段切换。当前 LoginRequest／LoginResponse 仅预留 thirdparty_bind_token 和 binding_required，密码登录携带非空 token 会明确拒绝；已实现字段与错误语义见 [服务端契约](../../../contracts/proto/xiaowei/server/README.md)。下述规则是后续实现约束，不代表已提供授权、注册或绑定接口。

thirdparty_bind_token 是短期随机凭据，有效期 15 分钟，由服务端关联已验证的第三方身份、发起设备和衔接用途；不作为业务登录态，不暴露于日志。它支持二选一：邮箱注册并绑定，或验证已有账号密码后登录并绑定。设备 ID 本身不是认证凭据，不能只凭该 ID 更改目标用户。

注册不带 thirdparty_bind_token 就是普通邮箱注册，不绑定第三方；携带有效 token 则注册和绑定在同一事务完成。携带无效、过期或已消费 token 时整个操作失败，不静默降级。注册还需验证邮箱并执行邀请／关闭注册策略。邮箱已存在时不自动合并，应让用户选择密码登录并携带 token。

密码登录携带有效 thirdparty_bind_token 时，账号密码验证通过后，将第三方绑定、token 消费、设备关联、旧会话撤销和新会话创建作为一个原子操作完成。错误密码不消费 token；事务失败不消费 token、不撤销旧会话，未过期时可修正后重试。第三方身份已绑定其他账号，或目标账号已有另一个同提供方身份时拒绝，不自动转移或合并。并发请求只允许一次消费成功。

独立绑定入口只服务于已登录用户，授权事务保存发起账号和会话，回调不能更换目标账号；会话在授权期间退出或被替换时拒绝绑定。已绑定当前账号视为成功，绑定到其他账号或当前账号已有不同微信身份时返回冲突。主动绑定不重新签发登录会话。

操作已提交但响应丢失时，通过普通邮箱密码或已绑定第三方重新登录恢复；不重复注册，不靠重放已消费 token 创建新账号。解绑、替换第三方身份和恢复策略仍属后续范围。


### 模块与依赖边界

HTTP／Gateway 接入层负责协议适配，账号规则在 `server/internal/auth/`，数据库事务在 `server/internal/db/`；SMTP 拟放 `server/internal/mail/`。依赖方向为接入层 → auth → db／mail；mail 不依赖 auth，db 不依赖 HTTP，通用 Gateway 不依赖账号业务。邀请签发接入已有 server 二进制，不增加公开签发 HTTP 接口。

服务端契约继续位于 `contracts/proto/xiaowei/server/`，桌面账号契约沿用 `xiaowei/account.proto`；按现有生成与 typed client 流程接入，不复制 HTTP 与 Gateway 的同义消息。桌面复用 `services/account/`、xwapi、设置账号区域及 Storybook；preload 不新增业务接口。

TS 远端 transport 归通用 Gateway，Go runtime 的位置按远端设计细化，认证连接适配放在 server。不得未经设计新增 npm package 或 Rust crate。微信复用现有用户表和设备会话，不另建账号体系；部署继续复用 `server/deploy/`。

时间、随机源和邮件投递在自动测试中可替换；事务、唯一约束和并发消费使用隔离真实 PostgreSQL 验证，不用内存假实现代替。自动测试不发送真实邮件；真实 SMTP 投递验收需要实际凭据及用户明确的发送指令。桌面现场验收遵守用户冷启动规则，生产登录默认由用户验证。
