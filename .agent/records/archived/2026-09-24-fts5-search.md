# 引入 Storage FTS5 全文检索能力

## Why

Storage 需要可供不同业务使用的中文全文检索基础。复用旧版 FTS5 自定义分词器，由数据库所属模块统一管理连接与注册，避免各业务重复引入数据库与分词依赖。剪贴板是首个预期应用场景，不定义底层能力的边界。

## What

本事项交付通用底层能力：迁入 `xw-tokenizer`，在 Storage 每条连接上注册，验证 FTS5 建表、写入、MATCH、snippet 及重开数据库后的可用性，并完成 Storage 原生构建。

具体业务的索引字段、同步触发器、历史回填、候选上限和排序策略由使用场景决定，不在本切片创建剪贴板 FTS 表或修改搜索接口。当前不预设通用索引管理协议。现有搜索行为见 [搜索实现](../../../docs/search.md)。

## How

当前逐连接注册、初始化与 FTS5 基础边界维护在 [Storage 数据库实现](../../../crates/xiaowei-storage/docs/database.md#fts5-与分词器注册)；分词模式、C 桥接与调用约定维护在 [xw-tokenizer](../../../crates/xw-tokenizer/README.md)。跨包业务分工见 [共享存储接入](../../../docs/storage.md#fts5-与搜索分工)。

迁移沿用旧版 `xiaowei std`／`xiaowei char`，采用用户公开 Jieba fork 的固定 revision `f6d5461001da18039fa0aca73f0b62ac80e130a7`；该版本与旧私有 revision `0269646` 代码相同，仅改写提交身份。保留 Yada 预构建词典与宏依赖，避免未经对比替换分词和初始化方案。C 桥接复用 bundled SQLite 头文件，与 Storage 对齐 SQLite 绑定来源，不另存头文件副本。

剪贴板接入验证发现旧桥接将展开子词放在独立 FTS 位置，导致连续词组漏匹配；修正为按偏移排序、覆盖词优先，并将重叠子词标记为同一位置。索引与 snippet 辅助分词顺序一致，查询继续使用原精确分词；该修正不更换词典或分词词集，历史临时索引未引入业务库兼容负担。

首个应用场景的业务索引、触发器、回填和召回维护在 [剪贴板事项](../active/2026-09-17-migrate-local-clipboard.md#剪贴板全文索引与召回)。全局 Search 的结果合并与 nucleo 重排不属于本事项范围。

## Alternatives considered

- 不直接替换公开 Jieba：旧 fork 含词典结构和初始化优化，未经对比不能认定等价。
- 不把 SQLite 数据库或 tokenizer 注册放入 Search：连接由 Storage 持有，每条池连接都必须能够使用同一 tokenizer。
- 不复制 SQLite 头文件：直接读取绑定 crate 提供的头文件，避免版本漂移。

Storage 的 SQL 由模块内部维护；SQL 类型与执行入口不对外暴露，napi／Gateway 只提供 typed KV、Settings 和 DAO。因此移除旧 SQL Gateway 设计遗留的 authorizer，不为 FTS5 维护 PRAGMA 白名单。保留单语句、参数数量、Query 只读等内部调用约定，以及 SQL／参数／结果预算、取消和事务回滚。外部输入仍经 typed 业务校验和 SQL 参数绑定，不转为外部 SQL 执行能力。

## Outcome

2026-10-07 按用户确认归档：原范围的 tokenizer 迁入、逐连接注册、查询／片段／重开验证和原生构建已完成，当前说明已沉淀至 Storage 与 tokenizer 文档。原记录中的桌面加载未验证边界保留，不补写 Agent 验证结果；剪贴板业务验收及全局 Search 接入分别属于其他事项。

底层能力已完成：迁入 `xw-tokenizer`，通过 GitHub 固定 revision 获取 Jieba 及其宏依赖；Storage 每条连接注册 tokenizer，FTS5 不依赖任何剪贴板 schema。未修改现有业务检索、Gateway 协议或 UI。

- `cargo test -p xw-tokenizer -p xiaowei-storage --locked`：20 项测试通过，包含旧分词测试、五连接池注册、中英文／前缀查询、经 SQL 校验的 snippet、数据库重开、可信内部 PRAGMA 执行及内部调用约定。
- 受影响包格式检查与 `cargo clippy --lib --no-deps -- -D warnings` 通过。扩大至依赖／全部测试目标时，被已有 `gateway/rust/src/event.rs` 的 `collapsible_if` 和 `storage/src/tests/settings.rs` 的 `bool_assert_comparison` 阻断；未修改无关代码。
- `pnpm --filter xiaowei-storage build:debug` 完成，已生成最新原生模块、JS 入口与类型声明；Storage 的 1 项 napi 生命周期测试通过。
- 当前 Hermes 工作区无运行实例；已通过 cwd 确认现有 Electron／nodemon 属于主工作区，未重启。桌面加载验证待用户启动 Hermes；本切片不新增可人工搜索的业务入口。

剪贴板业务索引与 DAO 召回由剪贴板事项承载，不改变本事项的底层能力边界；全局搜索合并仍未实施。
