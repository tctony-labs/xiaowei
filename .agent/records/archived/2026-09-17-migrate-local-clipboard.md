# 迁移本地剪贴板逻辑

## Why

复用旧版 Rust 剪贴板能力，建立 Electron 可调用的本地历史链路，去掉 Tauri 与公司服务依赖。

## What

本轮实现 macOS 文本（含长文本）、图片、文件路径采集，500ms 监听、去重、SQLite 持久化、分页与文本检索、按 ID 读取、复制回系统剪贴板、删除／清空普通历史和本地收藏。接入 main 生命周期与受限 preload API，本轮补充搜索入口和基础剪贴板面板，产品与 Storybook 共用组件。

## How

当前架构、数据和附件生命周期、搜索、编辑计次、时间字段、分类顺序与清理规则统一维护在[剪贴板](../../../docs/clipboard.md)。本节保留本次迁移的主要决策与取舍。

- 复用旧版 Rust 业务和系统 I/O 思路，移除 Tauri 与公司服务依赖；以 `xw-clipboard` 承担业务，napi 接入 Electron，产品和 Storybook 共用面板。旧版私有 UI 依赖按需迁入本地组件，不引入无法从公网获取的 `@tencent` 包。
- 数据库统一交给 Storage 连接池和 typed ClipboardDao，SQL 与 schema migration 收敛到 Storage，不引入 SeaORM。图片与长文本保留持久附件，资源操作解析记录身份后使用原文件，避免临时路径在重启后失效。
- 用户于 2026-10-25 确认采用完整内容 SHA-256，替代旧版长文本截断、大图采样和路径拼接 MD5。系统 `changeCount` 承担快速判变，监听计算的哈希由保存共用，兼顾大内容完整判重与稳定剪贴板的轮询成本；保留现有哈希、身份和附件命名，无需数据迁移。
- 分类按最后修改时间倒序排列，替代旧版按创建时间排序的对齐目标，不引入拖拽排序。旧分类的真实修改时间无法还原，升级时记为 0。
- 编辑属于修改历史，不属于使用：不写系统剪贴板、不增加次数、不刷新使用时间或置顶，合并也不累加来源次数。独立修改时间用于详情与清理保护；旧记录以升级前的使用时间近似初始化，不回算既有使用次数。
- 保留旧版面板内 FTS 查询语义，但数据库错误正常传播，不吞为无结果；列表排序次键采用 ID。全局 Search 的结果合并和 nucleo 重排留作独立工作。
